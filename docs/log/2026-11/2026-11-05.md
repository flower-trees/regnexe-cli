# 2026-11-05 开发日志

本日最终实现以第 2 节为准：打开会话即独占，state version 已移除。第 1 节保留初版实现与当时验证记录。

## 1. 会话执行互斥、指定任务恢复与版本保护

### 背景与范围

继续分析任务恢复中的副作用与并发风险。当前问题包括：同一持久化会话可被多个执行者推进；`/resume` 只记布尔标记，用户补充输入后重新选择最近更新任务；SQLite 以 INSERT OR REPLACE 无条件覆盖完整任务 JSON。

参考 Claude Code 的会话恢复与已有运行连接，以及 Codex 的 thread/turn/item 身份与生命周期，第一阶段明确执行身份和执行归属。没有把这些框架描述为对任意工具承诺 exactly-once，也没有推测它们未公开的锁实现。

### 实际改动

两个仓库均保留用户现有分支：CLI 为 `dev-0.1.1`，Agent 为 `dev-0.1.4`。

- Agent 版本改为 `0.1.4-SNAPSHOT`，CLI 引用相同快照，本机 Maven install 后完成集成打包；未向远程仓库发布快照。
- CLI 新增 `SessionExecutionLock`，按持久化 UUID 获取本地文件锁。同会话执行冲突报 busy；普通任务、恢复、直接 Skill 统一经过工作线程锁。锁随实际工作线程生命周期释放，主线程停止等待不会提前释放。锁文件不删除，进程退出后由操作系统释放文件锁。
- 暂停摘要写入移入锁内；`/clear` 清理历史也获取相同会话锁。
- `findOrCreateSession` 使用冲突不修改、随后重读的策略，防止并发同名创建返回不同 UUID 或覆盖获胜者工作目录。数据库身份读取失败时不再随机生成 UUID；数据库不可用时拒绝打开命名会话，只允许临时隐式新会话。
- `PendingResume` 固定 `sessionUuid/taskId/expectedVersion`；CLI 在锁内调用 Agent 新增的 `resumeTask(sessionId, taskId, expectedVersion, supplement)`。恢复先校验所属会话、版本、非完成状态，并成功保存 RUNNING 后才进入执行。保留旧 `resume` API 兼容，CLI 已切换到指定任务 API。
- SQLite 自动给旧任务表补充版本列，列值作为权威版本。保存只在修订匹配时更新，成功后递增；旧版本和已经删除的非零版本任务不能覆盖或重建记录。
- `TaskConflictException` 作为 Agent 控制信号传播，避免工具层转成普通失败后重试；执行阶段和顶层循环不会在冲突后再用旧快照写 FAILED。
- 内存 TaskStore 同样实现版本比较，使用独立序列化快照隔离嵌套轮次和 AI/Tool 消息。

### 限制与后续

- 锁作用于同主机、同锁目录、遵守协议的 CLI。Agent SDK 的其他宿主须自行提供会话串行化，不提供跨主机租约。
- 升级时避免旧版 CLI 与新版共同操作数据库；旧版不遵守本次锁和版本协议。自定义 TaskStore 需要实现新的版本保存契约。
- 不同会话可以竞争相同工作目录或外部资源。本次未实现工作目录隔离、资源级锁、远端 fencing。
- 未实现工具操作台账、UNKNOWN 状态、外部幂等键或远端结果核验。进程退出释放锁，不代表所有外部请求与残留子进程的副作用已经停止。

## 2. 最终约定：打开会话即占锁，移除 state version

### 决策

用户最终确认：`/resume` 预览任务即视为打开会话，打开后其他窗口不能再打开；等待输入和任务执行结束后继续占锁，切换会话或退出才释放。采用会话独占保障串行写入，去掉 version 相关逻辑，保持实现简洁。

### 实际改动

- `SessionContext` 持有会话锁，并负责打开、切换及关闭。CLI 启动（包含 `--session`）在初始化 Agent 前取得同一把锁。
- `/resume` 先获得目标会话的锁，再显示任务摘要。目标被其他窗口打开则拒绝；当前会话和原恢复选择保持不变。切换成功才释放原会话；重复打开当前会话复用锁。
- 普通任务、恢复及 Skill 不再每次获取/释放文件锁，而是引用已打开会话的锁。工作线程未退出时，即使主线程停止等待并关闭会话，也不会提前释放锁。
- `PendingResume` 仅保存会话 UUID 和任务 ID；执行时 `resumeTask(sessionId, taskId, supplement)` 按 ID 重新从存储加载，并检查归属、未完成状态。
- Agent 移除 `TaskExecutionState.version`、`expectedVersion`、`TaskConflictException` 和冲突传播逻辑；内存 TaskStore 恢复为原先的引用存储，同时删除为版本快照引入的消息反序列化类。
- SQLite 移除版本迁移和条件更新。新数据库不创建 version 列；旧数据库的遗留列不删除，保留为闲置兼容字段。旧任务 JSON 中的 version 可读取，下一次保存不再包含它。
- 重写设计文档 07，更新文档 04 的修订说明、索引及配置使用指南。初版方案和测试结果仍保留在本日志第 1 节，不能作为最终实现描述。
