# 持续输入、运行中补充指令与取消

实施日期：2026-11-05。目标是在任务运行时保持 CLI 可输入，普通消息补充当前任务，Esc 暂停，Ctrl+C 退出。

## 输入与任务执行

真实终端由主线程持续运行 JLine `readLine()`；`InteractiveTaskRunner` 在单独的工作线程中执行一个任务。输入线程不等待任务 Future，也不并发执行第二个任务。

- 空闲时普通输入启动任务。
- 运行时普通输入进入当前任务的补充消息列表，立即显示已接收提示。
- 任务正在停止或收尾时不接收补充，明确提示用户待结束后重发。
- 运行期间拒绝切换会话和插件操作；先 Esc 暂停，再执行斜杠命令。
- 管道输入保留原先串行 REPL，避免批量评测的多轮输入被当成同一任务的补充。

`AboveLineWriter` 将后台输出交给 JLine `printAbove()`，保留用户正在编辑的输入。工具确认通过 `InteractiveApproval` 邮箱请求，只有主输入循环读取终端，避免工具确认与输入循环抢读。确认支持 yes/no/always/pause；已有按会话 UUID 隔离的 always 记忆继续使用。

## 补充指令如何生效

`InteractiveChatModel` 装饰现有同步模型：

1. 在模型调用边界，把已接收消息追加为用户消息。
2. 将补充内容按顺序写入当前任务 goal，保存后可通过 `/resume` 继续。
3. 新输入到达模型等待期间，取消该次 HTTP 请求，携带完整补充消息重新请求；过期响应不交给工具执行器。
4. 工具正在执行时保持该工具继续，补充指令在后续模型请求接入。
5. 普通任务在收尾时若仍有未应用的补充，会保存并继续同一个 taskId。

模型 HTTP 取消通过当前请求对应的 OkHttp Call 实现。使用已有 HttpStreamClient 的公开配置接口安装拦截器，覆盖 common/chatGPT 两组客户端；每次模型调用建立线程范围，取消仅影响当前任务登记的请求。j-langchain 无需修改。

已完成的工具操作不会因补充消息被撤销。直接 Skill 沿用原设计，不创建 TaskExecutionState；若补充恰好发生在 Skill 完成之后，明确提示重发，不自动重跑有副作用的 Skill。

## Esc 暂停

Esc 立即显示正在暂停，并：

- 设置 Agent 与工具的取消信号；取消操作可重复调用。
- 取消实际模型 HTTP Call。
- 中断当前工具调用线程；Shell 复用已有取消检测、进程及子进程清理和部分输出保留。
- 解除工具确认的等待。
- MCP 调用取消时在后台关闭本地 transport，结束后重建 Agent/MCP 连接。

Guard 在工具开始前检查取消状态，防止暂停后继续执行后续工具。控制器一直保留 active 状态，直到实际工作函数和持锁清理退出；不使用 Future.cancel 的完成标记来判断实际任务已经停止。

Agent 在规划或网络等待中被取消时保存 PAUSED。CLI 同步保存补充指令和暂停摘要，保有会话锁直至落盘完成。暂停后可用 `/resume <name>` 预览并补充指令恢复。

## Ctrl+C 退出

Ctrl+C 在空闲和运行中均用于退出，替换旧的两次中断行为。先请求取消，执行器最多等待 3 秒清理；进程设置 5 秒退出兜底，避免不响应取消的调用或关闭钩子永久阻止退出。REPL 返回后关闭 Spring 上下文和框架执行器。

会话锁在退出清理时关闭；实际工作线程仍有引用时继续保留，直到退出或进程结束。外部服务已经提交的副作用不因关闭本地请求自动回滚。

## 验证

Java 回归验证任务单执行者、停止中的任务不能重叠、取消后工具不能开始副作用、确认邮箱解除等待，以及补充指令仅取消模型请求、Esc 清理幂等。

`evals/test_interactive_controls.py` 使用真实 PTY 和本地模拟模型 HTTP 服务，覆盖：

1. 模型不返回时可补充指令，同一任务保存补充并由 Esc 暂停。
2. 补充指令把原定文件写入改为另一文件，保持单一 taskId。
3. Shell 执行中 Esc 停止真实子进程，保留部分输出并保存 PAUSED。
4. 确认期间正常回答可完成任务，Esc 可取消确认。
5. 模型不返回时 Ctrl+C 及时退出。

测试不使用付费模型或 Opik。现有真实模型 `interactive_runner.py` 已适配持续提示符、任务完成通知和新快捷键，但本次未重跑官方模型四场景，也未验证真实外部 MCP 服务的取消与重连。部署环境仍应对所用 MCP 服务进行验收。
