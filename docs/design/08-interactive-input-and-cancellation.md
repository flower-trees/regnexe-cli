# 持续输入、运行中补充指令与取消

实施日期：2026-11-05。目标是在任务运行时保持 CLI 可输入，普通消息补充当前任务，Esc 暂停，Ctrl+C 退出。

## 输入与任务执行

真实终端由主线程持续运行 JLine `readLine()`；`InteractiveTaskRunner` 在单独的工作线程中执行一个任务。输入线程不等待任务 Future，也不并发执行第二个任务。

- 空闲时普通输入启动任务。
- 运行时普通输入进入当前任务的补充消息列表，立即显示已接收提示。
- 任务正在停止或收尾时不接收补充，明确提示用户待结束后重发。
- 运行期间拒绝切换会话和插件操作；先 Esc 暂停，再执行斜杠命令。
- 管道输入保留原先串行 REPL，避免批量评测的多轮输入被当成同一任务的补充。

`AboveLineWriter` 将后台输出交给 JLine `printAbove()`，保留用户正在编辑的输入。工具确认通过 `InteractiveApproval` 邮箱请求，只有主输入循环读取终端，避免工具确认与输入循环抢读。确认支持上下、左右方向键循环选择 no/yes/always/pause，Enter 确认，默认 no；文本回答继续兼容。`ApprovalNavigation` 通过 JLine widget 接管授权期间的方向键和确认键，菜单显示在底部状态区域；不支持该区域的终端显示普通文本选择行。方向键菜单启用时仅显示菜单，不再额外输出行式确认提示；纯文本模式保留原提示。授权结束后委托原光标/历史按键，菜单导航保留输入草稿。已有按会话 UUID 隔离的 always 记忆继续使用。

空闲时无参数 `/resume` 通过 `SessionPicker` 打开仅含名称的当前工作目录会话列表，默认当前会话；↑/↓ 切换、Enter 选择、Esc 取消。`ApprovalNavigation` 共用现有按键与底部显示区域，长列表滚动展示。选择结果交回主循环，按 `/resume <name>` 执行，因此历史加载与会话独占策略保持一致；浏览名称列表本身不打开或锁住目标会话。带参数 `/resume <name>` 直接恢复。列表与管道输出共用 RexDatabase.listSessions(Path)，只展示与当前主工作目录相同的会话；通过真实路径匹配目录别名，子目录单独处理。保留全局数据库查询供迁移等内部逻辑使用；带名称的恢复仍允许跨目录打开，之后按新的主工作目录筛选。管道模式下无参数命令只打印名称。

## 补充指令如何生效

`InteractiveChatModel` 装饰现有同步模型：

1. 在模型调用边界，把已接收消息追加为用户消息。
2. 将补充内容按顺序写入当前任务 goal，保存后可通过 `/resume` 继续。
3. 新输入到达模型等待期间，取消该次 HTTP 请求，携带完整补充消息重新请求；过期响应不交给工具执行器。
4. 工具正在执行时保持该工具继续，补充指令在后续模型请求接入。
5. 普通任务在收尾时若仍有未应用的补充，会保存并继续同一个 taskId。

模型 HTTP 取消通过当前请求对应的 OkHttp Call 实现。使用已有 HttpStreamClient 的公开配置接口安装拦截器，覆盖 common/chatGPT 两组客户端；每次模型调用建立线程范围，取消仅影响当前任务登记的请求。j-langchain 无需修改。

已完成的工具操作不会因补充消息被撤销。直接 Skill 沿用原设计，不创建 TaskExecutionState；若补充恰好发生在 Skill 完成之后，明确提示重发，不自动重跑有副作用的 Skill。

## Esc 暂停

Esc 立即显示正在暂停，并：

- 设置 Agent 与工具的取消信号；取消操作可重复调用。
- 取消实际模型 HTTP Call。
- 中断当前工具调用线程；Shell 复用已有取消检测、进程及子进程清理和部分输出保留。
- 解除工具确认的等待。
- MCP 调用取消时在后台关闭本地 transport，结束后重建 Agent/MCP 连接。

Guard 在工具开始前检查取消状态，防止暂停后继续执行后续工具。控制器一直保留 active 状态，直到实际工作函数和持锁清理退出；不使用 Future.cancel 的完成标记来判断实际任务已经停止。

Agent 在规划或网络等待中被取消时保存 PAUSED。CLI 同步保存补充指令和暂停摘要，保有会话锁直至落盘完成。暂停后可用 `/resume <name>` 预览并补充指令恢复。

## Ctrl+C 退出

Ctrl+C 在空闲和运行中均用于退出，替换旧的两次中断行为。先请求取消，执行器最多等待 3 秒清理；进程设置 5 秒退出兜底，避免不响应取消的调用或关闭钩子永久阻止退出。REPL 返回后关闭 Spring 上下文和框架执行器。

会话锁在退出清理时关闭；实际工作线程仍有引用时继续保留，直到退出或进程结束。外部服务已经提交的副作用不因关闭本地请求自动回滚。

## 验证

Java 回归验证任务单执行者、停止中的任务不能重叠、取消后工具不能开始副作用、确认邮箱解除等待，以及补充指令仅取消模型请求、Esc 清理幂等。

`evals/test_interactive_controls.py` 使用真实 PTY 和本地模拟模型 HTTP 服务，覆盖：

1. 模型不返回时可补充指令，同一任务保存补充并由 Esc 暂停。
2. 补充指令把原定文件写入改为另一文件，保持单一 taskId。
3. Shell 执行中 Esc 停止真实子进程，保留部分输出并保存 PAUSED。
4. 确认期间正常回答可完成任务，Esc 可取消确认。
5. 模型不返回时 Ctrl+C 及时退出。
6. 四方向键选择、默认 Enter 拒绝、always 授权保留，以及授权结束后的输入编辑与草稿保留。

测试不使用付费模型或 Opik。现有真实模型 `interactive_runner.py` 已适配持续提示符、任务完成通知和新快捷键，但本次未重跑官方模型四场景，也未验证真实外部 MCP 服务的取消与重连。部署环境仍应对所用 MCP 服务进行验收。


## 固定底部输入区

真实终端通过 DockedLineReader 保留 JLine 的编辑、历史与光标计算，将 Display 输出交给 ApprovalNavigation。在 JLine Status 中整体保留“上横线、可编辑输入、下横线、模型 · 会话 · 主工作目录”的底部区域；长输入可展开有限行数并随光标滚动。菜单在下横线和单行元数据之间显示。后台输出经 AboveLineWriter / printAbove 定位到上方滚动区域底端，保存和恢复输入光标，不能滚动输入区。提交的输入单独回显到历史输出区，不在固定区域打印换行。切换会话后刷新元数据。

终端尺寸变化后按新尺寸定位输入；不支持滚动区域或光标定位的终端保留原普通输入方式，管道输出不增加控制序列。终端自身进入滚动回看时由终端控制整个视口，返回实时视口后继续编辑。


## 应用内历史视图与状态

默认全屏模式进入备用屏幕，TranscriptViewport 保存最多 10000 个带样式的逻辑行，按当前宽度折行，并维护独立于底部编辑区的滚动偏移。鼠标滚轮、PageUp/PageDown 更新历史偏移；右侧应用内滚动条支持点击与拖动。回看时新增输出保持回看位置；普通跟随模式展示最新输出。窗口尺寸变化重新折行。DockedLineReader 保持唯一输入读取器，通过 JLine 鼠标事件读取器处理鼠标协议，不添加竞争读取线程。

ApprovalNavigation 在绘制历史后绘制固定底部区，包括活动状态、上横线、输入、下横线及一行元数据。InteractiveTaskRunner 在运行开始和结束通知状态条，授权菜单优先显示等待授权状态。尺寸由输入线程维护，取消线程绘制不执行 TTY 查询；退出时关闭鼠标跟踪并恢复原屏幕，关闭后的回调不再重绘。兼容模式 `ui.fullscreen: false` 保留普通终端滚动行为。

现场提交与历史回放采用相同的问答空行边界；AboveLineWriter 保留空行，不再 stripTrailing 丢弃间距。渲染器按 ui.color 配置给提示符、标题、行内代码和状态着色；TranscriptViewport 解析 ANSI 样式并保存为 AttributedString，重绘和滚动不会丢失配色。终端原生滚动条不受应用控制，默认全屏交互使用应用内滚动。
