## 1. 本周目标和范围

### 1.1 必须争取完成的业务闭环

仅选 `robot-description-style`，处理隔离测试库中的一个合成产品：

```text
读取该产品的事实和原始描述
→ 按 Skill 规则改写 description / detail_description
→ 确认改写内容和修改范围
→ 更新测试库中指定产品的这两个字段
→ 回读数据库并检查其他字段
→ 输出真实变更摘要和本次运行证据
```

完整闭环必须包含真实的测试库写入和回读，不能以生成文字、生成 SQL、dry-run 预览或模型说“已完成”替代。这里的“确认”是任务要求的产物/范围校验；测试任务的写入授权必须事先限定到测试库和目标记录，不能让非交互 Runner 卡在人机确认上。

数据库条件不具备时，明确记为阻塞或未完成；离线任务通过只能算前置诊断通过。计划不承诺在依赖受阻时仍能完成数据库闭环。

### 1.2 本周完成条件

- [ ] 指定 Skill 和自动选择使用同一条主执行链，相关行为有无模型回归证据。
- [ ] 工具与环境清单明确区分配置存在、运行验证通过、失败和未验证。
- [ ] 同一份离线任务，指定 Skill 和 Auto 各完成一次诊断，或留下可定位的失败证据。
- [ ] 一个单产品测试库任务完成读取、改写、写入、回读和字段保护验收。
- [ ] 每次付费运行能关联 Runner 结果、Opik Trace、模型、配置和实际用量。
- [ ] 周末报告明确本周通过什么、未通过什么、花费多少、下周先做什么。

### 1.3 本周不作为必达项

- 不建设 Inspect AI、HTTP Agent 服务或新评测平台。
- 不构建 30 条业务题，不做三种模式各重复三次，不开展统计显著性结论。
- 不完整导入品牌，不运行全库改写、全库评分或排序脚本。
- 不把联网搜索、动态网页抓取、上传 OSS 和文章生产一起纳入主线。
- 不重写全部 145 份 Skill，不为本周小任务先拆分大型接入品牌 Skill。
- 不引入多子 Agent 编排、阶段调度系统、自动无限追加轮次。

## 3. 执行纪律与预算

### 3.1 每次只推进一个检查点

1. 当前步骤有结论和证据后，才进入依赖它的下一步。
2. 先用普通程序验证工具，再让模型使用它；不让模型反复安装依赖、猜连接参数或排查认证。
3. 一次只执行一个用例、一个会话、一个工作目录，不并行运行，不复用旧对话历史。
4. 一次复测只改变一个主要因素：执行入口、元数据、上下文、工具或提示词不能同时大改。
5. 首次失败先保存轨迹、产物和部分执行结果，完成归因后才决定是否重跑。
6. 不清理用户文件，不修改用户全局模型/MCP 配置，不读取或输出密钥值，不把生产数据带入夹具。

### 3.2 起始预算建议

下表是待验证的首轮预算，不是对当前配置能力的描述。首次模型运行前，要把实际可执行限制写入本周独立评测配置，验证限制确实生效。

| 项目 | 离线描述任务 | 单产品数据库任务 |
|---|---:|---:|
| 主循环轮数 | 1 | 1 |
| 执行器最大迭代 | 4 | 8 |
| 全任务 LLM 调用上限建议，含规划/执行/反思及可能的摘要 | 6 | 10 |
| Runner 墙钟时间建议 | 120 秒 | 180 秒 |
| 输入加输出 Token 停跑观察阈值 | 30,000 | 50,000 |
| 自动重跑 | 0 | 0 |

- 首轮固定当前评测模型 `deepseek-flash`，不引入 Judge。核对实际请求模型和必要的输出长度配置，不在同一轮更换模型比较效果。
- 动态 `iterationsHint` 必须限制在本次执行器上限内，不能因为 Planner 估算较大就突破评测预算；同时记录请求值、估算值和实际应用值。
- 迭代数不是工具调用数，也不是全任务 LLM 次数。外层反思、摘要、执行异常重试都要计入实际用量；不能把配置中的 20 当成全任务硬上限。
- 优先落实已有轮次/时长限制及最小必要的调用次数控制，不为此建设通用预算平台。尚未具备的控制必须标注为未实现，不能声称已经硬限制。
- Token 阈值是停止继续运行/复测的观察阈值，不等于模型服务侧的严格 Token 熔断。记录中说明用量是否完整、是否估算，以及正在进行的单次请求可能超出观察阈值。
- 本周付费业务运行先按 5 次规划：2 次离线诊断、1 次数据库闭环、最多 2 次有明确修改依据的复测；额外运行先更新计划，不批量追加。
- 本周输入加输出 Token 累计到 150,000 时停止新增运行并复盘，不自动提高额度。这是起始成本控制方案，不能换算成未核实的人民币费用。
- 若 4/8 次迭代无法完成任务，先检查多余探索、过长输出、临近上限未收尾等原因；确实不足时单独调整一项预算并记录，不隐式“加到能过”。
