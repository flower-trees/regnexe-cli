## 1. 本周目标和范围

### 1.1 必须争取完成的业务闭环

仅选 `robot-description-style`，处理隔离测试库中的一个合成产品：

```text
读取该产品的事实和原始描述
→ 按 Skill 规则改写 description / detail_description
→ 确认改写内容和修改范围
→ 更新测试库中指定产品的这两个字段
→ 回读数据库并检查其他字段
→ 输出真实变更摘要和本次运行证据
```

完整闭环必须包含真实的测试库写入和回读，不能以生成文字、生成 SQL、dry-run 预览或模型说“已完成”替代。这里的“确认”是任务要求的产物/范围校验；测试任务的写入授权必须事先限定到测试库和目标记录，不能让非交互 Runner 卡在人机确认上。

数据库条件不具备时，明确记为阻塞或未完成；离线任务通过只能算前置诊断通过。计划不承诺在依赖受阻时仍能完成数据库闭环。

### 1.2 本周完成条件

- [ ] 指定 Skill 和自动选择使用同一条主执行链，相关行为有无模型回归证据。
- [ ] 工具与环境清单明确区分配置存在、运行验证通过、失败和未验证。
- [ ] 同一份离线任务，指定 Skill 和 Auto 各完成一次诊断，或留下可定位的失败证据。
- [ ] 一个单产品测试库任务完成读取、改写、写入、回读和字段保护验收。
- [ ] 每次付费运行能关联 Runner 结果、Opik Trace、模型、配置和实际用量。
- [ ] 周末报告明确本周通过什么、未通过什么、花费多少、下周先做什么。

### 1.3 本周不作为必达项

- 不建设 Inspect AI、HTTP Agent 服务或新评测平台。
- 不构建 30 条业务题，不做三种模式各重复三次，不开展统计显著性结论。
- 不完整导入品牌，不运行全库改写、全库评分或排序脚本。
- 不把联网搜索、动态网页抓取、上传 OSS 和文章生产一起纳入主线。
- 不重写全部 145 份 Skill，不为本周小任务先拆分大型接入品牌 Skill。
- 不引入多子 Agent 编排、阶段调度系统、自动无限追加轮次。

## 3. 执行纪律与预算

### 3.1 每次只推进一个检查点

1. 当前步骤有结论和证据后，才进入依赖它的下一步。
2. 先用普通程序验证工具，再让模型使用它；不让模型反复安装依赖、猜连接参数或排查认证。
3. 一次只执行一个用例、一个会话、一个工作目录，不并行运行，不复用旧对话历史。
4. 一次复测只改变一个主要因素：执行入口、元数据、上下文、工具或提示词不能同时大改。
5. 首次失败先保存轨迹、产物和部分执行结果，完成归因后才决定是否重跑。
6. 不清理用户文件，不修改用户全局模型/MCP 配置，不读取或输出密钥值，不把生产数据带入夹具。

### 3.2 起始预算建议

下表是待验证的首轮预算，不是对当前配置能力的描述。首次模型运行前，要把实际可执行限制写入本周独立评测配置，验证限制确实生效。

| 项目 | 离线描述任务 | 单产品数据库任务 |
|---|---:|---:|
| 主循环轮数 | 1 | 1 |
| 执行器最大迭代 | 4 | 8 |
| 全任务 LLM 调用上限建议，含规划/执行/反思及可能的摘要 | 6 | 10 |
| Runner 墙钟时间建议 | 120 秒 | 180 秒 |
| 输入加输出 Token 停跑观察阈值 | 30,000 | 50,000 |
| 自动重跑 | 0 | 0 |

- 首轮固定当前评测模型 `deepseek-flash`，不引入 Judge。核对实际请求模型和必要的输出长度配置，不在同一轮更换模型比较效果。
- 动态 `iterationsHint` 必须限制在本次执行器上限内，不能因为 Planner 估算较大就突破评测预算；同时记录请求值、估算值和实际应用值。
- 迭代数不是工具调用数，也不是全任务 LLM 次数。外层反思、摘要、执行异常重试都要计入实际用量；不能把配置中的 20 当成全任务硬上限。
- 优先落实已有轮次/时长限制及最小必要的调用次数控制，不为此建设通用预算平台。尚未具备的控制必须标注为未实现，不能声称已经硬限制。
- Token 阈值是停止继续运行/复测的观察阈值，不等于模型服务侧的严格 Token 熔断。记录中说明用量是否完整、是否估算，以及正在进行的单次请求可能超出观察阈值。
- 本周付费业务运行先按 5 次规划：2 次离线诊断、1 次数据库闭环、最多 2 次有明确修改依据的复测；额外运行先更新计划，不批量追加。
- 本周输入加输出 Token 累计到 150,000 时停止新增运行并复盘，不自动提高额度。这是起始成本控制方案，不能换算成未核实的人民币费用。
- 若 4/8 次迭代无法完成任务，先检查多余探索、过长输出、临近上限未收尾等原因；确实不足时单独调整一项预算并记录，不隐式“加到能过”。

## 5. 细分步骤与验收门槛

所有实施步骤初始为“待执行”，只按各步明确列出的依赖推进。P03 的数据库阻塞不妨碍 P05～P08 的离线工作，但不能据此绕过 P10、P11 的数据库门槛。

### P00 — 固定基线与工作区（无模型）

- [ ] 记录 CLI、Agent、技能仓库的分支、提交及未提交改动；不覆盖其他工作。
- [ ] 明确本地快照依赖来源；构建后记录实际 JAR、配置和 Skill 文件摘要，避免源码与运行产物不一致。
- [ ] 为本周定义独立临时工作目录、测试用户目录和结果目录，隔离全局 Skill、MCP、记忆与会话。
- 验收证据：一份版本/产物清单；所有结果可回指到具体基线。
- 停止条件：无法确认实际依赖版本或未提交改动来源，先记录并厘清，不调用模型。

### P01 — 盘点实际 Skill 加载（无模型）

- [ ] 重新统计 SKILL.md 和 frontmatter，记录缺失/异常，但先不批量修复材料。
- [ ] 在本周独立配置中显式接入 `.claude/skills`，验证 `robot-description-style` 的 ID、名称、描述和正文。
- [ ] 核对实际注册/启用数量、同名冲突、用户 Skill 污染；145 是文件数，不直接作为加载成功数。
- [ ] 后续自动选择诊断保留完整可加载候选集；缺元数据分组记录，不悄悄修好后冒充原样基线。
- 验收证据：文件数、注册数、启用数及其差异清单；目标 Skill 可解析。
- 停止条件：目标 Skill 缺失、错误覆盖或有无法解释的加载差异，先定位加载器/配置问题。

### P02 — 固定最小工具环境（无模型）

- [ ] 明确业务解释器；只安装本周必需依赖，不安装全部浏览器、搜索和上传栈。
- [ ] 验证 `pymysql` 等必要模块可导入；脚本相对路径、UTF-8 输出和工作目录正确。
- [ ] 检查受控 Shell 命令能返回退出码和有限输出，不通过模型排查 PATH、依赖或编码。
- [ ] 核对 Opik 服务、项目和关联字段；不把探活记录当成业务测评分数。
- 验收证据：解释器路径、依赖版本、命令/结果摘要；不包含任何密钥值。
- 停止条件：普通程序都不能正确调用的工具，不交给模型反复试。

### P03 — 提前确认测试库可获得（无模型）

- [ ] 确认专用测试库/测试账号来源，不复用或自动降级到生产配置。
- [ ] 核对 `lib/db.py` 的配置注入和 `.env` 加载位置，测试进程必须显式使用测试参数。
- [ ] 无法提供测试库时立即标记业务闭环阻塞，尽早暴露，不等到周五。
- [ ] 检查连接、读写超时是否明确；不以长时间等待或放宽全局 Shell 超时替代连接诊断。
- 验收证据：测试连接身份和库名校验的脱敏结果，或明确的阻塞原因。
- 停止条件：无法排除生产地址、没有授权测试账号，或目标库身份不明确。

### P04 — 定义唯一任务与人工验收答案（无模型）

- [ ] 准备一个合成产品：固定事实、原始描述、需要保留的型号/价格/封面/排序等哨兵字段。
- [ ] 逐条提取目标 Skill 的规则，明确允许修改的两个字段、不应编造的事实和输出格式。
- [ ] 先为离线场景准备 JSON 输入与可校验输出，再准备同一产品的测试库夹具；两者不使用不同业务要求。
- [ ] 规则检查事实和禁用表达，人工查看文风；不以单一标准答案逐字匹配，也不引入 LLM Judge。
- 验收证据：输入、预期不变量、检查清单和人工确认后的样例。
- 停止条件：无法说清什么算完成，先改任务定义，不调用模型。

### P05 — 统一“指定 Skill + Auto”入口（只改一条链）

- 前置：P00、P01、P04 通过。
- [ ] 指定 Skill 转成主任务的显式约束，进入与 Auto 相同的规划、执行、上下文和事件链；本周只支持固定一个 Skill。
- [ ] 未知、禁用或加载失败的指定 Skill 明确失败，不默默回退 Auto；Planner 不得替换或遗漏指定项。
- [ ] 第一版仅允许该指定 Skill 与基础工具；额外 Skill 如需使用先报告需求，不自动扩大任务范围。
- [ ] Auto 仍自行选择 Skill；不为它预先泄漏正确答案。
- [ ] 保持现有命令参数和显示目标含义；排查旧入口、暂停或恢复是否会绕回独立执行器。
- 验收证据：无模型测试验证正确 ID、错误 ID、启用状态、约束保留和共享执行路径。
- 停止条件：发现必须重构整套恢复/子 Agent 系统，收缩改动并单独记录设计，不带着两条不可比执行链开展收益对比。

### P06 — 验证预算和失败分类（无真实模型）

- 前置：P05 通过。
- [ ] 用模拟模型验证每类调用都能计数，明确外层轮数、执行器迭代、工具调用的区别。
- [ ] 验证动态预算不能越过本次硬迭代上限；对临近上限收尾、超限、工具非零退出和超时分别记录。
- [ ] 确认模型实际收到的工具输出规模，不以 UI 截断或 Trace 截断充当上下文限制。
- [ ] 关闭评测自动重跑；核对框架内部的失败重试是否仍发生，并把它纳入预算。
- [ ] 确认会话、授权、全局配置及既有回归没有被本次统一入口破坏。
- 验收证据：模拟调用次数、应用的预算、失败标签与对应回归结果。
- 停止条件：无法确认限制生效，或出现无界重试，不开始付费试跑。

### P07 — 离线指定 Skill 单次诊断（第 1 次模型运行）

- 前置：P01、P02、P04～P06 通过。此步不依赖数据库可用。
- [ ] 在新会话中提交固定输入，指定 `robot-description-style`，仅输出两个字段。
- [ ] 禁止联网、数据库读写和上传；可用工具只覆盖必要文件读写。
- [ ] 核对指令实际注入、输出与事实一致、没有无意义安装/目录探索/反复读取。
- [ ] 保存 Runner 输出、实际用量、迭代、工具结果和 Trace；人工检查改写质量。
- 验收证据：规则结果、人工备注、产物与运行链接；通过前不跑下一条。
- 停止条件：预算耗尽、工具越界、未产生可信结果或观察证据缺失，进入 P09，不自动重试。

### P08 — 同一离线任务的 Auto 单次诊断（第 2 次模型运行）

- 前置：P07 通过。
- [ ] 新会话、同一输入、同一工具与预算；保留完整可加载候选，不显式指定 Skill。
- [ ] 核对目标是否进入候选、是否被选中、实际注入与产物是否符合要求。
- [ ] Auto 错选或未选时先检查元数据和 Planner，不能立刻提高预算或更换模型。
- 验收证据：候选/选择/注入/执行/产物的对应关系，以及两条诊断的成本分解。
- 停止条件：本周只得到两条诊断轨迹，不据此计算稳定成功率、Skill Gain 或统计显著性。

### P09 — 一次只处理一个主要问题（最多 2 次有依据的模型复测）

- [ ] 失败归类：加载/元数据、选择、指令遵循、工具环境、执行预算、上下文、观察链路。
- [ ] 先做无模型复现和最小修复，再决定是否需要模型复测。
- [ ] 记录改动前后唯一主要变量、预算变化和预计影响；只重跑相关失败任务。
- [ ] 同一问题一次修复后仍失败，再定位原因，不连续碰运气；复测额度用完就复盘。
- 验收证据：问题、复现、修改依据、针对性结果；原始失败记录保留。
- 停止条件：问题扩展为大重构或成本超过阈值，优先保留已验证成果并标记剩余阻塞。

### P10 — 建立单产品数据库夹具（无模型）

- 前置：P03、P04 通过；可在离线诊断阶段并行安排人工准备，但不并发运行模型任务。
- [ ] 按实际 SQL 需要建立最小 MySQL 表/字段；不要因 CLI 自身用 SQLite 就用 SQLite 替代业务 MySQL 语义。
- [ ] 只放一个目标合成产品和少量哨兵记录；保存写入前快照，准备清理和重置方法。
- [ ] 普通程序先完成读取、受控事务写入/回滚或恢复、再次查询，验证账号权限和字段语义。
- [ ] 选择最小字段更新方式；目标 Skill 已指出 `update_robot()` 可能清空未传字段，不用它做描述局部更新。
- [ ] 证明测试进程不会读取生产 `.env` 或回退到生产库；只向测试工具提供最小测试凭证，生产凭证不继承到评测进程，密钥不进入提示词或结果。
- 验收证据：合成数据快照、字段保护检查、连接/查询时长和重置结果。
- 停止条件：表结构、权限、超时或不变量检查未通过，不进行模型写库。

### P11 — 单产品数据库闭环（第 3 次模型运行）

- 前置：P07、P10 通过，P08 已有明确诊断结论；任何可能影响指定路径或写库安全的未解释故障都已关闭。若 Auto 仅有已定位的选择/元数据缺陷，可保留该缺陷记录，用已验证的指定路径完成本步，不冒称 Auto 已通过。
- [ ] 首次采用“指定 Skill + Auto 主链”，避免同时新增选择与数据库两类变量。
- [ ] 任务只授权更新目标产品的 `description` / `detail_description`，明确不处理其他产品，不重建评分/排序/素材。
- [ ] 验证真实读取、改写、最小字段更新和回读；工具返回成功不等于任务验收成功。
- [ ] Runner/独立检查程序核对两个字段、其他字段和哨兵记录；人工核对事实与文风。
- [ ] 保存前后差异、实际命令/SQL 的脱敏证据、执行状态、用量和 Trace；按夹具方案重置。
- 验收证据：数据库前后状态和全部不变量通过，最终摘要与真实结果一致。
- 停止条件：未授权字段变化、错误库、结果与回答不一致，立即停跑并保留证据，不能用再次运行覆盖现场。
