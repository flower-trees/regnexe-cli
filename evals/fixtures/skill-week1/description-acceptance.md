状态：任务、夹具与参考草稿已准备；参考文风待用户人工审阅。未执行模型、数据库建夹具或业务写入。此处不是一次评测结果。

## 输入与对比条件

唯一用例见 [description-case.json](description-case.json)。产品与型号均为合成数据，封面使用不可用的 example.invalid，不触发联网。离线与数据库阶段使用同一份事实和原始描述；后者仅在 P10 增加实际 ID、schema 所需字段和前后快照，不改变改写要求。

Auto 与指定模式获得相同任务提示和产品数据，Auto 不注入 Skill 名称或标准答案。目标 Skill 标识、规则和参考答案属于评测端元数据，不应把整个夹具原样作为 Auto 提示。后续 Runner 只投递 auto_prompt、facts 和 before；指定模式额外注入显式 Skill 约束。两种模式不得读取参考答案。

## 规则与证据

| 规则来源 | 验收方式 | 判定 |
|---|---|---|
| 两字段定位、字段用反 | 简介非空且概括产品类别/用途；详细描述承接特点 | 结构自动检查，定位与文风人工复核 |
| 不出现“官网” | 两字段搜索“官网” | 出现即失败；来源备注无须机械保留 |
| 不堆砌详细参数 | 不出现 Markdown 表格或原始“自由度：…；负载：…”清单 | 格式初筛；是否堆砌人工复核，不将数字数目当通用规则 |
| 清除内部分析笔记 | 检查“本记录”“type_id”“待官网”“未采集”“历史误设”等本例污染片段 | 命中则失败；同义改写仍需人工看语义 |
| 不编造、按信息量分段 | 保留六轴、教学演示/轻型搬运、负载 3kg、半径 600mm、拖拽示教这些本例固定事实；不能更改数值或增加未知事实 | 数字与事实初筛；完整语义人工复核 |
| 最小写库 | 只改 description/detail_description，不调用 update_robot | 数据库阶段看工具轨迹、目标完整行差异及事务回读；离线标为不适用 |
| 不修改其他字段或记录 | 型号、价格、封面、排序等哨兵保持一致，目标与邻近行对比 | P10 明确真实 schema 与快照，P11 核验；仅回答“已保留”不能通过 |

输出约定：离线输出恰好两个字符串字段的 JSON；这是评测输入合同，不是 Skill 自带的 JSON 要求。本例简介/详情均非空，详情一段即可，不要求固定三段。事实可分布于两字段，中文数字、单位空格或同义表达不能仅因字符串不同判错。上述关键事实全保留是本用例的内容合同，不推广为所有 Skill 任务的通用规则。

自动检查只覆盖格式、明确污染和不变量；文风、事实蕴含与隐性编造留人工审阅，不引入 Judge，也不把关键词通过冒充任务成功。具体评分器与分类实现留 P06。
